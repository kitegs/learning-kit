## 已核实的缺陷

- P1：导入笔记被知识图谱引用后，未编辑正文时仍能撤销删除，导致来源断开；真实工具/图谱模块与内存数据库复现。
- P2：40 条待确认记录会挤掉较早的已执行历史，8 条界面上限无分页；实际 listOperations 与前端等价过滤复现。
- P2：MCP 状态读取乱序覆盖较新状态；真实 Pinia store + 可控模拟 IPC 复现。

这里只做用户请求的检查，记录 BUG 和索引，不修业务代码、不改架构、不提交或推送。既有脏工作区保留。诊断仅使用内存数据库，无真实用户文件写入；不把此次复现视为全量测试/构建或人工验收。

## 收敛顺序

1. 先补撤销引用保护，再修列表过滤/分页和刷新竞态。
2. 将工具中心的队列、历史、确认/拒绝/撤销、刷新和错误状态收敛到一个有类型的 store；界面保留运行步骤与操作队列不同用途，统一工具事实来源。
3. 统一工具名称、展示标签和能力元数据，保留桥接/主进程双重输入校验与来源权限边界；不机械合并 Agent 状态和数据库操作状态。
4. MCP 写入回执/状态查询减少全文回传，全文只供桌面预览，减少外部 AI 的重复上下文消耗；桥接不直接调用模型，但工具输出仍可能进入外部模型上下文。
5. 知识点导入与图谱创建统一同名规则：当前 artifact 导入允许同名，graphNodeSave 拒绝同名。先明确是允许重名还是提示复用，不能默认按标题合并不同知识。
6. 最后补真实 AI 宿主配置、真实模型调用、人工 smoke 与发布/安装包验收；目前只验证源码开发与生产构建运行。

暂不建议为这些问题拆 Java/Python 服务或引入 Agent 编排框架；问题位于本地状态同步、数据引用与现有工具服务边界。修复后再根据性能数据决定是否需要更大调整。
