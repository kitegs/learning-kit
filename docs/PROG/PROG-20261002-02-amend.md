# 实现

- 新增共享 AiDiagnostic、AgentRun、AgentStep 类型；诊断类使用单调时钟采集耗时、首次内容和经校验的服务商 usage；失败仅存固定分类/HTTP 状态，不存原始错误、API Key 或正文。
- SSE 消费保留 finish_reason 后的 usage，读取到 DONE/EOF；requestUsage 独立默认关闭，避免强制未知服务支持扩展参数。主聊天诊断默认开启，其他旧调用不隐式新增记录。
- 新表 ai_request_diagnostics / agent_runs，仅新增 CREATE TABLE IF NOT EXISTS，不修改现有列；通过 schedulePersist 节流保存。诊断最近 200 条，执行列表最近 40 条，无新依赖。
- 新增 IPC ai:diagnostics:list/clear、ai:agent:list/prepare/decide，handler/preload/env 三处同步；请求/事件仅增加可选字段，不修改已发布方法或返回值。新增 useAiWorkflowStore 管理渲染层读取。
- Agent 默认关闭：一次模型生成 → 有界工具预览 → 等待确认 → 执行。模型、每个工具及重试计入 2–20 步预算；超限整批拒绝，不自动重复模型调用。
- 复用 tool-service 的预览、确认、事务和撤销。失败重试只重新预览，仍需确认；操作记录作为事实来源，成功/撤销步骤不重放。重启中断旧模型，恢复待确认及失败工具。
- 新运行记录面板支持执行阶段、预览、确认/拒绝、失败重试与诊断清空；设置有开关和步骤上限，取消设置恢复草稿。关键生命周期、时钟和状态恢复已加中文注释。
- 实际界面测试发现结束事件与 invoke 返回竞态：加入等待终止事件的握手、5 秒有界等待和旧回调 epoch 保护。用户停止释放等待，不污染新一轮。

# 验证与边界

- npm run typecheck、npm test、npm run build 通过；存在原有 Sass/Rollup 警告。
- ai-workflow.cjs 覆盖计时、未知 usage、窗口归属、整批步骤预算、预览零业务写入、确认、重复执行拒绝、失败重试与预算、外部撤销同步、重启恢复、诊断保留上限和清空。
- ai-workflow.e2e.cjs 与 --dev：真实 Electron + 临时用户目录 + 本地 SSE；实际输入框发送、工具预览、确认、重启后继续确认、诊断末尾 usage、超限、HTTP/坏流、停止、关闭诊断、清空与持久化通过。初期 dev 参数错误已修正测试启动器，并成功重跑。
- artifacts/ai-workflow/agent-flow.png 与 request-diagnostics.png 是实际 UI 截图，模拟服务用量为输入 80/输出 40，非云端账单。
- 不修改实际用户资料；不安装 native 包，不改 CSP、默认 system prompt 或 ACTION 格式；不提交、不推送。
- 真实云端流式、停止和连接测试、开发模式人工 smoke 尚未验收。因此 REQ/DEV 保留进行中/impl，不声明完整验收。
