# 业务决策: SQLite 由 better-sqlite3 改用 sql.js

## 背景
初次安装 `better-sqlite3` 在多台 Windows 上均卡 gyp 原生编译：
- MSVC v143 找不到 ClangCL 工具集
- 装 Clang 后 `llvm-lib.exe` 退出码 1（疑似 vcpkg 注入的 LIB 路径冲突）
- 走 prebuild 二进制因 GitHub timeout 失败

继续在工具链上耗下去会卡死所有用户在 `npm install` 阶段。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 修 native 工具链 / 让用户都装完整 VS | 性能好，API 同步 | 普通用户根本不会装；不可持续 |
| B. better-sqlite3 走 npmmirror 二进制 | 免编译 | 仍依赖 yarn/Windows Version 等；不稳定 |
| **C. 改用 sql.js（WASM）** | 零原生编译，一键装；API 兼容 SQL；功能对本项目够用 | 全表加载到内存；大库慢；写盘需手写节流 |
| D. IndexedDB/Dexie | 纯前端存储 | 主进程拿不到，跨端 / 文件副本管理麻烦 |

## 决定
**选 C**。

## 影响
- 影响：`electron/main/db.ts` 全重写为 initSqlJs + export → 写盘；所有 IPC helper 改用 prepare+bind+free；不再用 stmt cache（重复 sql.js statement 会"Statement closed"）
- 不影响：渲染层 `window.lk.*` API、schema、功能
- 后续注意：写 IPC 要在末尾 `schedulePersist()`；不要在 hot path 直接 `persist()`
