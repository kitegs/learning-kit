# 快捷键冲突与便签跨页竞态

## 现象

- `Ctrl+Shift+N` 会先命中 `Ctrl+N`。
- 添加便签或快速翻页后可能回到第一页，同位置便签在其他页面出现。

## 根因

- 快捷键逻辑只校验必需修饰键，没有拒绝多余修饰键。
- `renderPage()` 在多个 `await` 后读取可变的 `page.value`；旧渲染完成时会按新页码查询、显示或保存批注。
- 便签事件回调也使用当前页码而非数据行所属页码。
- 目录重建先软删除，再以相同 ID upsert 时没有清除 `deleted_at`，导致重开后目录消失。
- 翻页保留旧滚动位置，可能直接落到新页面底部；便签文本只监听 `change`，未失焦关闭时可能丢失。

## 修复

- 使用共享的精确快捷键匹配器。
- 渲染固定页码并用 epoch 丢弃过期结果。
- DOM 便签记录页码，所有回调使用捕获页码；坐标改为相对书页。
- 目录 upsert 恢复软删除行；翻页回到顶部；便签输入采用 350ms 节流自动保存。

状态：fixed。
