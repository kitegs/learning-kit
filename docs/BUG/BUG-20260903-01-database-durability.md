# 问题

sql.js 持久化直接覆盖主数据库文件，写入失败只记录控制台；启动时主数据库无法打开会静默创建空数据库。断电、磁盘写入失败或文件损坏时，用户可能看到空资料且无法判断原文件是否仍可恢复。

## 修复

- 数据先写入临时文件并刷新到磁盘，通过 SQLite 完整性校验后再原子替换主文件。
- 替换前保留上一份有效数据库为 `.last-good.bak`。
- 启动依次检查主文件、待提交临时文件、最近有效副本和恢复前副本；从副本恢复时保留异常主文件。
- 所有候选文件都无效时停止启动，不创建空库覆盖用户判断。
- 保存状态广播到渲染层；底部状态栏和设置页显示失败并提供重试。
- 关闭应用前保存失败会取消关闭并提示用户。

## 回归验证

自动化测试覆盖正常替换、上一版本备份、无效写入不覆盖主文件和主文件损坏后选择有效副本。
