# PDF 阅读位置与便签保存存在切换竞态

## 现象

- 翻页后快速切换模块，页码只在整页渲染结束时保存，重新进入可能回到旧页。
- 缩放重绘可以短暂保持视野，但切换模块或重启后只恢复页码，不恢复缩放与页内位置。
- 便签文字使用局部延迟计时器；输入后立即切换或退出时存在未写入窗口。
- 便签拖动和文字输入分别基于旧数据保存，拖动后再输入可能把位置覆盖回旧坐标。

## 根因

- 阅读页码、缩放、滚动锚点和 PDF 渲染完成状态耦合在同一个异步函数中。
- 组件在 `onUnmounted` 才尝试抓取最终视口，此时书页 DOM 已被移除，只能得到页顶默认值。
- 每个便签 DOM 自己持有计时器和初始数据快照，重绘与卸载无法统一刷新，坐标与文字也没有使用同一份实时快照。

## 修复

- 页码变化立即进入串行保存链；每本书的缩放和归一化页内锚点写入现有设置表。
- 缩放、滚动、模块切换和应用关闭统一刷新阅读状态；在 `onBeforeUnmount` 抓取仍存在的书页位置。
- PDF 重绘增加过期请求和卸载保护，预期的销毁不再形成未处理拒绝。
- 便签改用组件级待保存队列，重绘、失焦、切换和关闭均会刷新；坐标与文字从当前 DOM 同时生成。
- 新增隔离的 PDF UI 回归，覆盖文本标记、透明手绘荧光笔、便签、切换模块和重启恢复。

## 验证

隔离测试生成临时三页 PDF 与测试资料库。完整流程连续三次通过，未访问真实用户数据。
