# 统一知识收集箱：第一阶段方案

## 设计

复用 `notes` 作为知识沉淀的统一载体，并用已有 `links` 表记录 `message -> note` 的 `saved_to_knowledge` 关系。这样无需改动已发布 schema 的列定义，也能为后续书摘、导图和卡片的统一沉淀复用同一关系模型。

## 流程

1. 消息菜单调用 `notes:create-from-message`。
2. 主进程查找或创建根级 `收集箱` 文件夹，创建笔记并写入关系。
3. 渲染层展示结果，并可跳转到知识库或新笔记。
4. 知识库页读取笔记与关系，提供基础来源、收集箱、标签筛选。

## 兼容性

- 仅新增 IPC，preload 和 `env.d.ts` 同步新增声明。
- 不修改 `db.ts` 的既有表列定义；`links` 为既有通用关联表。
- 数据库写操作均调用 `schedulePersist()`。
