# 产品收敛版本实施方案

## 实施顺序

严格按阶段推进。上一阶段没有通过退出检查，不开始下一阶段；每阶段单独形成可回退的 Git 提交。

### 阶段 0：冻结与建立基线

1. 保存当前工作区快照，整理未提交文件，避免收敛修复与历史功能混在一个提交。
2. 建立功能状态表：稳定、实验性、隐藏、未完成；不再以文档状态代替实际验证。
3. 记录四条 P0 流程的当前失败点、测试数据和复现步骤。
4. 跑现有类型检查、测试、构建和 smoke test，得到可比较基线。

退出检查：当前变更可追溯；每个已知 P0 问题都有稳定复现方法；不存在来源不明的生成文件。

### 阶段 1：数据安全与可恢复保存

1. 将 sql.js 落盘改为临时文件写入、校验、替换的可恢复流程，保留最近有效副本。
2. 数据库读取失败时停止静默创建空库，展示恢复入口并保留损坏文件。
3. 统一保存状态：未保存、保存中、已保存、保存失败；失败必须可重试。
4. 核对数据库和 localStorage 的职责，把会影响内容恢复的状态纳入可备份存储；纯界面偏好可以继续留在本地设置。
5. 增加数据库关闭重开、写入中断和备份恢复测试。

退出检查：模拟保存失败或损坏后，原资料仍可恢复；应用不会把空库误报为正常资料。

### 阶段 2：笔记核心链路稳定

1. 明确一个笔记正文作为唯一数据源；纸页、目录和双页布局只做投影，不再分别改写正文。
2. 把粘贴规范化、分页计算和保存序列集中到共享路径，删除页面级重复修补。
3. 固化混合内容粘贴、公式、表格、图片、跨页输入、全选、撤销/重做、空白拖动画布和锚点跳转行为。
4. 保持现有存储格式可读；如需新增格式版本，只做兼容迁移并保留恢复路径。
5. 只在明确职责边界拆分 `OpenNotebookEditor` 和 `NotesView`，不为未来功能新增抽象。

退出检查：笔记 P0 自动化流程连续三次通过；关闭重开后内容、对象和导航位置一致。

### 阶段 3：电子书核心链路稳定

1. 分离阅读位置、缩放、页面渲染和批注状态，避免缩放或重绘重置滚动锚点。
2. 统一文本选择、荧光标记和手写批注模式；透明度和参数从工具栏、右键与设置读取同一份状态。
3. 便签、目录、关联笔记和阅读进度全部绑定书籍 ID 与页码，禁止跨页复用视图状态。
4. OCR 仅保留稳定的手动识别与目录导入；复杂文字层编辑继续标记实验性。
5. 按页面渲染、导航、批注、目录/OCR 四个真实职责拆分 `PdfReaderView`，不新增通用框架。

退出检查：缩放、翻页、标记、便签、切换模块和重启恢复流程连续三次通过。

### 阶段 4：对话整理与体验统一

1. 以完整 user + AI 轮次为唯一拖拽单位，折叠组只保存关系与顺序，不复制或隐藏消息正文。
2. 拖拽、搜索移动、跨对话移动和标题层级调用同一移动命令，并提供明确落点提示。
3. 使用本地测试模式覆盖无限对话、折叠、展开、跨对话移动和重启恢复。
4. 收口快捷键、右键菜单、中文文案、焦点、保存反馈和主题文字对比度。
5. 将未完成的 MCP、习题集和 OCR 编辑文字层显示为实验性，避免用户误认为已经稳定。

退出检查：对话结构没有孤儿消息或重复关系；核心入口无需查文档即可发现。

### 阶段 5：发布候选验证

1. 将核心测试纳入统一命令，避免 OCR、工具服务和 UI 测试长期游离在默认测试之外。
2. 使用隔离的测试数据执行笔记、PDF、对话和恢复四条端到端流程。
3. 检查错误日志、中文文案、空状态、键盘导航和护眼主题对比度。
4. 补充用户 README、数据目录说明、备份恢复说明和实验功能清单。
5. 连续三次完成类型检查、测试、构建、启动、关闭重开和持久化验证。

退出检查：无 P0 缺陷；已知 P1 有明确记录和规避方式；满足 REQ 的全部验收标准。

## 最小技术边界

- 不在本版本替换 Tiptap、PDF.js、Tesseract.js 或 sql.js。
- 不引入状态机、事件总线库、测试框架或新的 UI 框架，除非现有能力无法写出可重复验证。
- 优先复用现有 IPC、Pinia store、测试脚本和组件；只在重复缺陷确实来自共享根因时抽取函数。
- 新 IPC 必须同步 handler、preload 和 `env.d.ts`；数据库演化只能新增表或迁移字段。
- 自动测试和恢复测试必须使用隔离数据，禁止接触真实 `userData/data`。

## 提交与回滚

- 阶段 0 完成后建立基线提交；之后每个阶段至少一个独立提交。
- 不把格式化、无关重构和功能修复混入同一提交。
- 每个阶段提交前执行类型检查、相关测试、全量测试、构建和一次手动 smoke test。
- 出现数据兼容或持久化回归时立即回退当前阶段，不继续叠加界面补丁。

## 推荐执行批次

| 批次 | 内容 | 优先级 |
|---|---|---|
| A | 阶段 0 基线 + 阶段 1 数据安全 | P0 |
| B | 阶段 2 笔记稳定 | P0 |
| C | 阶段 3 阅读器稳定 | P0 |
| D | 阶段 4 对话与体验统一 | P0/P1 |
| E | 阶段 5 发布候选验证 | P0 |

第一批实施前先处理当前大型未提交工作区；未经确认不自动提交或丢弃用户已有改动。
